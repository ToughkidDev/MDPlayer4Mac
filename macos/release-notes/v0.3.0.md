MUC 컴파일과 MUB 재생을 MucoMSX 툴체인(2026-11-10)과 같게 맞췄습니다. MUC에서 만드는 MUB 파일이 MucoMSX의
muc2mub 출력과 바이트 단위로 같고, 곡 시작의 초기화 쓰기를 빼면 재생 중 음원 칩에 쓰는 값도 MucoMSX
재생기(MUBPLAY)와 같습니다.

## 변경 사항

### MUC 컴파일

- mucomDotNET 확장 문법이 없는 곡은 원본 MUCOM88 v1.7과 같은 클래식 MUB8로 컴파일해 클래식 드라이버로
  재생합니다. 확장 문법이 있는 곡은 MucoMSX와 같은 muPb·msPb 형식으로 씁니다. 이전에는 모든 곡을
  mucomDotNET 모드로 컴파일했습니다.
- 원본처럼 1열에서 시작하는 트랙 선언만 연주 행으로 읽습니다. 들여쓴 행은 무시합니다.
- 바로 이어진 쉼표만 합치고, 행 끝 `&`는 다음 행의 같은 음과 이어집니다(MucoMSX와 같음).
- MUB 형식(헤더, 페이지 배치, 템포 위치, 데이터 끝 바이트)과 태그 블록이 MucoMSX와 같습니다. 태그에는
  헤더 전체의 `#` 행만 넣고, 빈 행과 `;` 주석 행은 넣지 않습니다.
- MucoMSX가 컴파일하지 않는 소스는 같은 오류 번호와 문구로 거부합니다.
  - 오류 19: 헤더의 `#pcm` 태그에 적은 PCM 파일이 없을 때(이름에 `?`·`*`가 있어도 같음). 값이 빈
    `#pcm`은 MucoMSX처럼 컴파일합니다.
  - 오류 17: 한 줄이 1,023바이트를 넘을 때. MucoMSX처럼 MSX 전용 문법 곡(PSGS·OPLS 행, `?`·`@` 명령이
    있는 MSX/SCC 행)에는 적용하지 않습니다.

### 재생

- MSX-MUSIC과 OPNA를 함께 쓰는 곡에서 `H`(하드웨어 LFO) 명령 뒤에 FM 팬이 다른 채널의 값으로 바뀌던 문제를
  수정했습니다. 팬·LFO 값을 칩마다, 채널·페이지마다 따로 보관합니다.
- mucomDotNET 모드 곡에서 디튠이나 LFO로 F-number가 옥타브 경계를 넘을 때, MUCOM88 v1.7과 MucoMSX처럼
  디튠을 그대로 더합니다. 이전에는 옥타브를 옮기며 음이 약 12센트 높아졌습니다. FM3 확장(S) 슬롯은
  MucoMSX와 같이 기존 방식을 유지합니다. MSX-MUSIC 비브라토 깊이 차이도 이 수정으로 해결됐습니다.
- SSG·SCC 파트가 끝나는 틱에도 소프트웨어 LFO를 한 번 더 진행합니다(MucoMSX와 같음).

### 앱

- 단일 파일로 배포된 앱에서 설정이 저장되지 않고 늘 기본값으로 돌아가던 문제를 수정했습니다.

### MDPlayer4Web

- 브라우저판 MDPlayer4Web을 추가했습니다. macOS판과 같은 화면과 엔진을 쓰며 GitHub Pages
  (https://toughkiddev.github.io/MDPlayer4Mac/MDPlayer4Web/)에서 실행됩니다. MIDI·RCP는 지원하지 않습니다.

## 검증

- MucoMSX 시험 곡 1,458곡(VGM 변환 곡 제외): MDPlayer4Mac이 MUC에서 만든 MUB가 MucoMSX 툴체인 출력과
  1,458곡 모두 바이트 단위로 같습니다. 오류 17·19로 거부되는 곡은 없습니다.
- 같은 1,458곡을 MucoMSX 재생기와 틱 단위로(곡마다 3,600틱) 비교했습니다. 1,193곡은 모든 칩 쓰기가 같고,
  265곡은 곡 시작의 초기화 쓰기만 다릅니다(들리는 차이 없음). 연주 중 다른 곡은 0곡입니다(이전 48곡).
- 오류 17·19 규칙과 위 재생 규칙을 확인하는 회귀 검사를 추가했습니다. 독립 코어·MSX 재생 회귀 검사를
  통과했고, GitHub 배포 작업에서도 다시 검사합니다.
- 자동 검사이며 전곡 청음이나 원본 게임 전체와의 파형 동일성 검증을 뜻하지 않습니다.
