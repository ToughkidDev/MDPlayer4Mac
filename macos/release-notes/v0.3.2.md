MUC 컴파일을 MucoMSX 툴체인(2026-11-18)과 다시 맞췄습니다. `#pcm` 태그의 새 규칙을 따르고, 더 큰 시험 곡 묶음에서
찾은 출력 차이(기본 템포, MSX 파트의 템포 기록, 겹친 매크로)를 고쳤습니다.

## 먼저 알아 둘 것

- **K 파트(ADPCM)에 음표가 있는 MUC는 헤더에 `#pcm` 태그가 있어야 합니다.** 없으면 MucoMSX와 같이 오류 20으로
  열리지 않습니다. 이전에는 태그가 없어도 `mucompcm.bin`을 찾아 썼습니다. 그렇게 쓰던 곡은 헤더에 `#pcm` 한 줄을
  넣으면 됩니다(이름 없는 `#pcm`은 `MUCOMPCM.BIN`을 뜻합니다).

## 변경 사항

### MUC 컴파일

- `#pcm` 규칙 (MucoMSX 2026-11-17):
  - K 파트에 음표가 있는데 `#pcm` 태그가 없으면 오류 20 "K part needs a #pcm tag". 쉼표와 제어 명령만 있는
    K 파트는 그대로 컴파일합니다.
  - 이름 없는 `#pcm`은 `MUCOMPCM.BIN`을 씁니다. 그 파일이 없으면 오류 19입니다. 이전에는 그냥 컴파일했습니다.
  - `#pcm` 태그가 없으면 `MUCOMPCM.BIN`을 찾지 않습니다.
  - PCM 파일은 K 파트에 음표가 있을 때만 MUB에 붙습니다(`@n`만 있으면 붙지 않음).
- 템포 명령(`t`/`T`)이 하나도 없는 곡은 MucoMSX처럼 Timer-B 225로 컴파일합니다. 이전에는 0이 들어가 MucoMSX와
  빠르기가 달랐습니다.
- OPNA와 MSX 칩을 함께 쓰는 곡에서 MSX 파트(`MSXA`…)에 쓴 템포를 MucoMSX와 같은 바이트로 씁니다.
- 매크로를 5단 이상 겹쳐 부르는 곡은 MucoMSX처럼 확장 형식(muPb)으로 씁니다.
- MucoMSX가 컴파일하지 않는 소스를 같은 오류 번호로 거부합니다.
  - 오류 16: 매크로를 9단 이상 겹쳐 부를 때(MucoMSX의 한도는 8단).
  - 오류 9: MSX 전용 문법 곡(PSGS·OPLS 행, `?`·`@` 명령이 있는 MSX/SCC 행)의 소스가 MucoMSX의 입력 창 하나를
    넘을 때. 받아들이는 가장 큰 소스는 14,976바이트입니다(주석 포함).

### 재생

- PCM이 들어 있지 않은 MUB의 태그가 이름 없는 `#pcm`이면 MUB와 같은 폴더의 `MUCOMPCM.BIN`을 읽습니다.
- PCM이 들어 있지 않은 MUB의 `#pcm` 파일을 찾지 못하면 이전처럼 PCM 없이 연주하고, 상태 줄에
  "PCM file not found: 파일 이름"을 보여 줍니다.
- `#pcm`·`#voice` 등 곡과 함께 두는 파일을 정확한 이름으로 찾지 못하면 대소문자를 가리지 않고, 그다음에는
  8.3으로 잘린 이름(예: `bosco_pcm.bin` → `BOSCO_PC.BIN`)으로 찾습니다. MSX용 SD 카드에서 복사한 폴더를 그대로
  열 수 있습니다.
- 시퀀서(칩에 쓰는 값과 시점)는 이번에 바뀌지 않았습니다.

## 검증

- 시험 곡 1,955개(MUCOMSX 저장소의 Samples/Muc 461개와 변환 곡 1,494개)를 컴파일해 MucoMSX의 출력과
  비교했습니다.
  - 1,925개는 MSX-DOS 2.20에서 실제 MUC2MUB `/P`가 만든 MUB와 바이트 단위로 같습니다.
  - 28개는 `#voice` 파일 이름이 8.3보다 길어 MSX에서는 음색 파일 없이 컴파일되는 곡입니다. 음색 파일을 준
    MucoMSX 컴파일러(호스트에서 실행)의 출력과 바이트 단위로 같습니다.
  - 2개는 MucoMSX가 거부하는 곡이고(오류 9, 오류 16) 같은 번호로 거부합니다.
  - v0.3.1은 이 가운데 32개의 MUB가 MucoMSX와 달랐고, 거부해야 할 2개를 컴파일했습니다.
- 새 규칙은 작은 시험 곡 46개를 MSX-DOS 2.20의 MUC2MUB로 직접 컴파일해 결과(오류 번호 또는 MUB)를 맞춰
  봤습니다. `#voice` 파일이 없는 2개만 다릅니다: MucoMSX는 메시지 없이 컴파일하고, MDPlayer4Mac은 이전처럼
  오류로 알립니다.
- 위 규칙을 확인하는 회귀 검사를 추가했습니다. 독립 코어·MSX 재생 회귀 검사를 통과했고, GitHub 배포 작업에서도
  다시 검사합니다.
- 자동 검사이며 전곡 청음을 뜻하지 않습니다. 재생기와의 틱 단위 비교는 이번에 다시 하지 않았습니다(시퀀서 변경
  없음).
