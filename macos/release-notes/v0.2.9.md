음악 데이터가 64KB를 넘는 MUB/MUC 곡이 재생 도중 멈추던 문제를 수정하고, 60,000바이트 이상인 MUC 소스를
규격 밖으로 보고 거부하도록 바꿨습니다.

## 변경 사항

- 컴파일러: 반복 `[ / ]`의 주소를 16비트로만 보관해, 곡 전체의 음악 데이터가 64KB를 넘으면 앞 파트의 데이터를
  덮어쓰던 문제를 수정했습니다. 한 반복은 한 파트(64KB 미만) 안에만 있으므로 출력 위치 바로 아래의 주소로 복원합니다.
- 드라이버: 파트의 루프 위치가 64KB 경계 너머에 있으면 루프 오프셋이 음수가 되던 문제를 수정했습니다.
- 두 문제로 D·E 파트가 함께 있는 곡처럼 데이터가 큰 곡이 재생 시작 직후나 도중에 멈출 수 있었습니다.
- 60,000바이트 이상인 MUC 소스 파일은 MUCOM88 규격에 맞지 않으므로 컴파일하지 않고 거부합니다(59,999바이트까지
  허용). 상태줄에 파일 크기와 함께 이유를 표시합니다. 이미 만들어진 `.mub` 파일에는 적용하지 않습니다.
- MUC 컴파일 오류도 일반 "재생할 수 없음" 메시지 대신 컴파일러가 알려 준 이유를 상태줄에 표시합니다.

## 검증

- 음악 데이터 66,308바이트, 반복과 루프 위치가 64KB 경계 뒤에 있는 시험 곡으로 확인했습니다. 수정 전에는 다른 파트의
  데이터가 덮어써지고 0.51초에 멈췄으며, 수정 후에는 전체 곡의 해당 파트 바이트가 단독 컴파일 결과와 같고 끝까지
  재생됩니다.
- 저장소의 기존 MUC 39곡은 수정 전후의 컴파일 결과가 바이트 단위로 같습니다.
- 59,999바이트 MUC는 컴파일되고 60,000바이트 MUC는 거부되는지 검사하는 회귀 검사를 추가했습니다.
- 릴리즈 전 독립 코어 및 오디오 엔진 회귀 검사와 UI 빌드를 수행하고, GitHub 배포 작업에서도 재검사합니다.
- 자동 검사이며 전곡 청음이나 원본 게임 전체와의 파형 동일성 검증을 뜻하지 않습니다.

## 알려진 제한

이전 버전의 장시간 곡 루프 감지, 일부 들여쓴 비연주 행 전처리와 압축 행 `/` 반복 탈출 제한은 그대로입니다.
반복 탈출 `/`가 음악 데이터의 정확히 0x10000·0x20000 위치에 오는 드문 경우는 여전히 탈출 지점이 없는 것으로 읽힙니다.
